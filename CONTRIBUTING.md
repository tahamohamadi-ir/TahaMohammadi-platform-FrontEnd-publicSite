# Contributing

Work from a task in `TASK-LIST.md` or an approved task specification. Link any contract or design decision affected by the change. Keep commits focused and do not mix generated files or unrelated cleanup.

Before review, run the repository's documented formatting, lint, type, unit, component, build, accessibility, and browser checks. Until the runtime scaffold exists, validate Markdown links and prohibited placeholders. Visual changes require desktop and mobile evidence in both locales and both themes.

If an API, route, locale, content, or asset contract is unclear, stop at the boundary and record the decision needed; do not manufacture a local assumption.
